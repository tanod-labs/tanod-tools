What URL encoding does

A URL may only contain a limited set of ASCII characters, and some of them have a job: / separates path segments, ? starts the query, & and = split it into names and values, # starts the fragment. Percent-encoding writes any other byte as % followed by two hex digits, so a value such as R&D / 2026 can travel inside a query string without being mistaken for structure: R%26D%20%2F%202026.

Text is first turned into UTF-8 bytes, which is why one accented letter becomes two escapes and an emoji becomes four. Decoding reverses the process and checks that the bytes form valid UTF-8. This tool decodes with its own strict reader, so instead of a generic "URI malformed" error it tells you which escape is broken and where.

The three modes match the three common situations. Encode a single value (component) when you are building a query parameter or a path segment. Encode a whole URL only when you have a complete address with spaces or non-ASCII letters in it. Use form data for the body of a form post or a query string built the way HTML forms build it.

Tips

  • Need a clean, readable path instead of escapes? Make one with the slug generator.
  • Binary data in a URL is usually Base64url, not percent-encoding: try Base64 encode and decode.
  • A token in a query string that starts with eyJ is probably a JWT. Read it with the JWT decoder.
