Client Hints from your browser

What a user agent tells you, and what it hides

The user agent started as a way for a server to see which browser was asking, so it could send a page that worked there. Browsers then copied each other's names to get the good pages, which is why a Chrome string today says Mozilla, AppleWebKit, KHTML, Gecko and Safari as well. A parser works around this by testing patterns in a careful order and picking the most specific match.

The string is also being shortened on purpose. Chrome's User-Agent reduction fixes the Windows version at NT 10.0, the macOS version at 10_15_7, the Android model at K and the build number at 0.0.0, so that the string is no longer a good fingerprint. The details have not gone away: a page that asks for them through Client Hints gets the platform version, architecture, model and full browser version, and the visitor's browser decides whether to answer.

Use the string for coarse decisions and logs, not for trust. Crawlers and command-line tools such as curl send their own short strings, and anything can be spoofed. If you are chasing a layout bug, feature detection in the page is more reliable than reading the browser name.

Tips

  • A server log full of 403 or 429 responses to one client? Look the codes up in the HTTP status code reference.
  • User agents in URLs or query strings are often percent-encoded; decode them with URL encode and decode.
  • Headers copied from a request sometimes carry Base64 values; read them with the Base64 encoder and decoder.
