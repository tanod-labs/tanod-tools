From YAML to JSON


YAML and JSON describe the same kind of data: mappings, lists and simple values. YAML is written by people, with indentation instead of braces, comments, and shortcuts like anchors; JSON is what most programs and APIs expect. Converting between them is common when a Kubernetes manifest, a Compose file or an OpenAPI description has to be fed to something that only reads JSON.


Some YAML features have no JSON equivalent, so the converter resolves them. An anchor (&base) marks a block that an alias (*base) can reuse, and a merge key (<<) copies a mapping's entries into another; in JSON each of those becomes a full copy. Comments are dropped, because JSON cannot hold them. A file with several documents separated by --- becomes a JSON array.


The type rules follow YAML 1.2: true and false are booleans, null and ~ are null, numbers are numbers, and everything else, including yes and 2024-05-01, is text. Syntax errors carry a line and column, and the most frequent causes are a tab used for indentation, a key repeated in the same mapping, and a value that is not indented under its key.


Tips


    
  
  • Need to go the other way? JSON to YAML quotes values like "yes" so they survive the trip.

  • Check or tidy the result with the JSON formatter.

  • Got tabular data instead? CSV to JSON covers spreadsheets.
