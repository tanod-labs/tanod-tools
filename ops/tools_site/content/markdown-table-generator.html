How a Markdown table is written

A GitHub-flavored Markdown table is plain text: a header row, a row of dashes that sets the alignment, and one line per data row, with cells separated by pipe characters. It is the format GitHub renders in READMEs, issues and pull requests, and many other tools, including documentation sites and note apps, understand it too.

The grid holds the cells; the first row is the header. Each column has an alignment. Left is written :---, centre :---:, right ---:, and none is plain dashes. Cell text is escaped where needed: a pipe becomes \|, and a line break becomes the HTML tag <br>. The tool then lines up the columns with spaces so the source reads like a table, using the width of each character rather than its byte count so accented letters line up.

Pasting from a spreadsheet is the quickest way to start. Spreadsheets put copied cells on the clipboard as tab-separated text, with one line per row, and the grid reads that directly. CSV and TSV files work the same way through the paste box, with quoted fields and quoted line breaks handled. If you paste an existing Markdown table, the cells and alignments are read back into the grid so you can change them.

Tips

  • Have JSON instead of a spreadsheet? Convert it first with JSON to CSV, then paste the result here.
  • See how the table will look with Markdown to HTML.
  • Going the other way, from a web page back to Markdown, use HTML to Markdown.
