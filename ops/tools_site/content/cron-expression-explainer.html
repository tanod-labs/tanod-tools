    Reading a cron schedule

    Cron checks its table once a minute and runs every job whose five fields all match the current time, with one exception for the two day fields described below. So */15 9-17 * * 1-5 means: at minutes 0, 15, 30 and 45, in hours 9 to 17, on any day of the month, in any month, Monday to Friday. The last run of the day is at 17:45, because the hour field covers the whole of hour 17.

    The explainer parses each field the way Vixie cron and cronie do, which is what most Linux distributions ship. Names for months and weekdays are accepted in any case and 7 counts as Sunday. A step after a single number, such as 5/10, is read as 5-59/10 the way many cron versions read it; some older ones reject it, so the tool reminds you to write the range out. Ranges must run from low to high: FRI-MON is flagged rather than wrapped around, because standard cron does not wrap ranges.

    Next run times are worked out by stepping through the calendar in the time zone you choose, so an expression that can only match on 29 February finds the next leap year at once, and one that can never match, such as 0 0 31 2 *, is reported as never running.
