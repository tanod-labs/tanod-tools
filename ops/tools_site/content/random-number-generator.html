Why a secure generator, and what "random" has to mean here


A fair draw means every allowed value is equally likely and one draw tells you nothing about the next. Math.random() is fast but is a predictable sequence in disguise, and it is fine for animations, not for a prize draw. The browser's crypto.getRandomValues is seeded from the operating system and is the right source for anything people might argue about.


Turning raw random bits into a number from 1 to 6 is where many tools go wrong. A 32-bit value has 4,294,967,296 possibilities, which 6 does not divide, so using the remainder makes the low faces fractionally more likely. The fix is rejection sampling: the largest multiple of the range size below 232 is the cut-off, and a draw above it is discarded and redrawn. For ranges wider than 32 bits the tool draws exactly as many bits as needed and rejects anything over the range, using big integers so values near 9,007,199,254,740,991 stay exact.


Decimals use the same idea on a grid. With two decimal places, the range 0 to 5 is treated as the integers 0 to 500, one is drawn and the point is put back, which keeps every grid value equally likely instead of rounding a continuous number.
