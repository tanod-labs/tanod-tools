      DHCP on RouterOS, piece by piece

      RouterOS keeps a DHCP server in three places, and a missing piece is the usual reason clients get no address. The pool is just a named set of address ranges. The server listens on one interface and leases addresses from its pool. The network entry is matched by subnet and holds the options sent with each lease: gateway, DNS servers, domain name and NTP servers. The interface also needs the router's own address in that subnet, or the server has no network to serve.

      The page checks the pieces against each other before writing anything: the gateway and pool must sit inside the subnet, the pool must avoid the network, broadcast and gateway addresses, and static leases must be unique and inside the subnet. Static leases are written to /ip dhcp-server lease with the server's name, so each device always gets the same address.

      Tips

      • Planning the addressing? The subnet calculator shows the host range and size of any prefix.
      • One DHCP server per VLAN: create the VLAN interfaces first with the VLAN generator, then run this once per VLAN.
      • If the router answers DNS, make sure the firewall drops DNS from the internet.
