Making SQL readable


A database reads a query the same way whether it sits on one line or forty, which is why queries pasted from logs, ORMs and monitoring tools so often arrive as a single unbroken string. Formatting puts each major clause (SELECT, FROM, WHERE, GROUP BY, ORDER BY) on its own line and indents the columns, conditions and subqueries beneath it, so you can see the shape of the query at a glance and spot a missing join condition.


The layout follows the dialect you pick, because the words and symbols differ between databases. A PostgreSQL cast such as price::numeric, a numbered parameter like $1, a MySQL backtick name, an Oracle CONNECT BY clause and a SQL Server TOP 10 are all valid in one dialect and a syntax error in another. Placeholders for bound parameters (?, $1, :name, @name) are recognised and left alone.


Keyword case has no effect on how a query runs, so it is purely a house style. A formatter that understands the grammar can change it safely, because it knows which words are keywords and which are column names or text inside quotes.
