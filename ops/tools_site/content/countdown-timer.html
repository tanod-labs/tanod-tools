How a timer stays accurate, and what a hidden tab does to it

The obvious way to build a countdown is to subtract one from a number every time a one-second timer fires. It is also wrong. Browsers throttle timers in background tabs to once a second or even once a minute, and a busy page delays them further, so a counted-down timer quietly falls behind. This page stores the moment the timer should finish and, on every tick, subtracts the current time from it, using the monotonic clock for durations and the wall clock for dates. Ticks only decide when the screen is redrawn.

Date mode works with calendar time, which is messier. "Midnight on 1 January in Auckland" is a different instant from the same clock reading in London, and twice a year some zones skip or repeat an hour. The page asks the browser's time zone database for the exact offset on the target day, so a countdown to a local event is correct for the place it happens, whatever zone the viewer is in.

The announcements for screen readers are deliberately sparse: the start, each whole minute, 10 and 5 seconds, and the end. Reading out every second would make the page unusable with a screen reader and would not help anyone who can see the digits.

Tips

  • Planning an event across regions? Compare clock times first in the time zone converter.
  • Want elapsed time rather than time left, with laps? Use the stopwatch.
  • Need the gap between two dates in days, not a live clock? Try the date difference calculator.
