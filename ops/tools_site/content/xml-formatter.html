Pretty-printing XML without changing it


XML is picky about structure and relaxed about layout: between two tags you may put nothing, a space, or a hundred blank lines and the document means the same thing. That is why feeds, SOAP responses and exported configuration often arrive on one long line. Indenting each nested element makes the hierarchy visible and makes a line-by-line comparison possible.


Many formatters parse the document and write it back out, which can quietly rewrite things you did not ask them to touch: turning &#169; into a literal character, changing quote styles, or reordering attributes. This tool reads the text with a tokenizer and re-uses each piece exactly as it was written, adding or removing only whitespace between elements. It then uses the browser's own XML parser to check that the result is well-formed.


Whitespace is the one place where XML is not always relaxed. In a paragraph such as <p>one <b>two</b> three</p> the spaces around the tags belong to the text, so moving or removing them would change what a reader sees. Elements that mix text and tags, and elements marked xml:space="preserve", are therefore never reflowed.
