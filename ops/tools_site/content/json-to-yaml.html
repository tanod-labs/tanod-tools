Turning JSON into readable YAML


YAML is largely a more human-friendly way to write the same data JSON holds. Braces and quotes give way to indentation and plain words, which is why configuration for Kubernetes, Compose and CI systems is usually written in it. Starting from JSON, such as an API response or a generated manifest, the conversion is mechanical, but one detail needs care: YAML decides a value's type from how it looks.


In YAML a bare true is a boolean, null is null and 1.0 is a number. A JSON string that happens to look like one of those, such as "null", "1.0" or "0x1F", must be quoted in the YAML or it will change type when read. The converter quotes exactly those, plus empty strings and text that starts with symbols that have a meaning in YAML, and then checks the output by reading it back.


Multi-line text becomes a literal block, which is far easier to read than a long string with \n escapes. Empty objects and arrays are written as {} and []. Because JSON has no comments, the YAML starts without any; you can add your own afterwards.
