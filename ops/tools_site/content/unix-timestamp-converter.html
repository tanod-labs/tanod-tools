How epoch time works

A Unix timestamp counts seconds from the Unix epoch, midnight UTC on 1 January 1970. Because it names a moment rather than a clock reading, the same number means the same instant in Manila, London and New York. Converting it to a date is where time zones come in: the tool uses your browser's time-zone database, the same rules your operating system uses, to work out the local offset and daylight saving at that moment.

Many systems use finer units. JavaScript and Java count milliseconds, some databases and Python's time.time_ns() use microseconds or nanoseconds. Pasting such a value as seconds gives a date tens of thousands of years away, so the tool guesses the unit from the number's size and shows which it chose. Microsecond and nanosecond values keep their extra digits in the ISO 8601 line.

Going from a date to a timestamp needs a time zone, because 09:00 happens at a different moment in each zone. The date you type is read as a clock reading in the zone you pick. Readings that fall in a daylight-saving gap or overlap are flagged, so you know which instant you got.

  • Schedules written as cron expressions can be checked with the Cron expression explainer, which lists the next run times in any zone.
  • UUID version 7 values carry a millisecond timestamp; the UUID generator can read it.
