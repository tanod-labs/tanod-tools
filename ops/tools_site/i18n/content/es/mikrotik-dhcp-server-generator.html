      DHCP en RouterOS, pieza por pieza

      RouterOS guarda un servidor DHCP en tres lugares, y la falta de una pieza es la razón habitual por la que los clientes no reciben dirección. El pool es solo un conjunto con nombre de rangos de direcciones. El servidor escucha en una interfaz y asigna direcciones de su pool. La entrada network se asocia por subred y contiene las opciones que se envían con cada lease: gateway, servidores DNS, nombre de dominio y servidores NTP. La interfaz también necesita la dirección propia del router en esa subred, o el servidor no tiene una red que atender.

      La página contrasta las piezas entre sí antes de escribir nada: el gateway y el pool deben estar dentro de la subred, el pool debe evitar las direcciones de red, de broadcast y del gateway, y los leases estáticos deben ser únicos y estar dentro de la subred. Los leases estáticos se escriben en /ip dhcp-server lease con el nombre del servidor, de modo que cada dispositivo siempre reciba la misma dirección.

      Consejos

      • ¿Planificando el direccionamiento? La calculadora de subredes muestra el rango de hosts y el tamaño de cualquier prefijo.
      • Un servidor DHCP por VLAN: crea primero las interfaces VLAN con el generador de VLAN y luego ejecuta esto una vez por VLAN.
      • Si el router responde DNS, asegúrate de que el firewall descarte el DNS que viene de internet.
