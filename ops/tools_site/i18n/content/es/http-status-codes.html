Cómo leer los códigos de estado HTTP

Los códigos de estado HTTP son el primer dato de cada respuesta: un número de tres dígitos que le dice al cliente qué pasó con su solicitud. El primer dígito indica la familia: 1xx para mensajes de progreso, 2xx para éxito, 3xx para redirección, 4xx para un problema con la solicitud y 5xx para una falla en el servidor. Un programa que no conoce un código concreto puede actuar correctamente mirando ese primer dígito, y por eso se pueden agregar códigos nuevos sin romper los clientes antiguos.

La lista oficial se mantiene en el registro de códigos de estado HTTP de IANA, y los significados están escritos en el RFC 9110 (HTTP Semantics) y en algunos otros RFC para WebDAV y extensiones. La frase después del número, como Not Found, es solo una etiqueta; HTTP/2 y HTTP/3 no la transmiten. Algunas frases cambiaron de nombre en 2022, así que 413 ahora es Content Too Large y 422 es Unprocessable Content.

Los servidores también inventan códigos fuera de los estándares. nginx registra 499 cuando un cliente cuelga, y Cloudflare usa del 520 al 526 para describir fallas entre su red y tu servidor de origen. Aquí aparecen en un grupo aparte para que no se confundan con los códigos registrados. Al depurar, recuerda que el código que ves puede venir de un proxy o una CDN delante de tu aplicación, no de la aplicación en sí.

Consejos

  • ¿Una solicitud falla y su dirección tiene caracteres especiales? Codifícala o decodifícala con Codificar y decodificar URL.
  • Lee el cuerpo de la respuesta de un error de API con Formatear y validar JSON.
  • ¿Un 403 para un navegador o bot concreto? Revisa qué envía el cliente con el Analizador de user agent.
