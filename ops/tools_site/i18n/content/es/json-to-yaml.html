Convertir JSON en YAML legible


Convertir JSON a YAML es sencillo porque YAML es, en buena medida, una forma más amigable de escribir los mismos datos que contiene un JSON. Las llaves y comillas dan paso a la sangría y a palabras simples, y por eso la configuración de Kubernetes, Compose y los sistemas de CI suele escribirse en YAML. Partiendo de un JSON, como la respuesta de una API o un manifiesto generado, la conversión es mecánica, pero hay un detalle que exige cuidado: YAML decide el tipo de un valor según su apariencia.


En YAML, un true sin comillas es un booleano, null es nulo y 1.0 es un número. Una cadena JSON que se parezca a alguno de ellos, como "null", "1.0" o "0x1F", debe ir entre comillas en el YAML o cambiará de tipo al leerse. El convertidor pone entre comillas exactamente esas, además de las cadenas vacías y del texto que empieza con símbolos que tienen significado en YAML, y luego comprueba el resultado volviendo a leerlo.


El texto de varias líneas se convierte en un bloque literal, mucho más fácil de leer que una cadena larga con escapes \n. Los objetos y arreglos vacíos se escriben como {} y []. Como JSON no tiene comentarios, el YAML empieza sin ninguno; puedes agregar los tuyos después.
