De YAML a JSON


YAML y JSON describen el mismo tipo de datos: mapeos, listas y valores simples. YAML lo escriben personas, con sangría en lugar de llaves, comentarios y atajos como las anclas; JSON es lo que esperan la mayoría de los programas y las API. Convertir YAML a JSON es habitual cuando un manifiesto de Kubernetes, un archivo de Compose o una descripción OpenAPI tiene que pasarse a algo que solo lee JSON.


Algunas funciones de YAML no tienen equivalente en JSON, así que el conversor las resuelve. Un ancla (&base) marca un bloque que un alias (*base) puede reutilizar, y una clave de fusión (<<) copia las entradas de un mapeo en otro; en JSON cada uno de ellos se convierte en una copia completa. Los comentarios se descartan, porque JSON no puede contenerlos. Un archivo con varios documentos separados por --- se convierte en un array JSON.


Las reglas de tipos siguen YAML 1.2: true y false son booleanos, null y ~ son nulos, los números son números y todo lo demás, incluidos yes y 2024-05-01, es texto. Los errores de sintaxis indican línea y columna, y las causas más frecuentes son un tabulador usado para la sangría, una clave repetida en el mismo mapeo y un valor que no está indentado bajo su clave.
