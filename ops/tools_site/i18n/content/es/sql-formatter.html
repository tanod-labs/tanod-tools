Hacer que el SQL sea legible


Una base de datos lee una consulta igual si está en una línea o en cuarenta, y por eso las consultas copiadas de registros, ORM y herramientas de monitoreo suelen llegar como una sola cadena sin cortes. Formatear SQL pone cada cláusula principal (SELECT, FROM, WHERE, GROUP BY, ORDER BY) en su propia línea y sangra debajo las columnas, condiciones y subconsultas, para que veas la forma de la consulta de un vistazo y detectes una condición de join que falta.


El formato sigue el dialecto que elijas, porque las palabras y los símbolos cambian de una base de datos a otra. Una conversión de PostgreSQL como price::numeric, un parámetro numerado como $1, un nombre de MySQL entre comillas invertidas, una cláusula CONNECT BY de Oracle y un TOP 10 de SQL Server son válidos en un dialecto y un error de sintaxis en otro. Los marcadores de parámetros enlazados (?, $1, :name, @name) se reconocen y se dejan intactos.


Las mayúsculas de las palabras clave no afectan cómo se ejecuta una consulta, así que son solo una cuestión de estilo de cada equipo. Un formateador que entiende la gramática puede cambiarlas sin riesgo, porque sabe qué palabras son palabras clave y cuáles son nombres de columna o texto entre comillas.
