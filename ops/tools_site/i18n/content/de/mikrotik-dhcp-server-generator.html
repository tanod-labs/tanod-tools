      DHCP unter RouterOS, Teil für Teil

      RouterOS hält einen DHCP-Server an drei Stellen, und ein fehlendes Teil ist der übliche Grund, warum Clients keine Adresse bekommen. Der Pool ist nur eine benannte Menge von Adressbereichen. Der Server lauscht auf einem Interface und vergibt Adressen aus seinem Pool. Der Network-Eintrag wird über das Subnetz zugeordnet und enthält die mit jeder Lease gesendeten Optionen: Gateway, DNS-Server, Domainname und NTP-Server. Das Interface braucht außerdem die eigene Adresse des Routers in diesem Subnetz, sonst hat der Server kein Netz zu bedienen.

      Die Seite prüft die Teile gegeneinander, bevor sie etwas schreibt: Gateway und Pool müssen im Subnetz liegen, der Pool muss Netz-, Broadcast- und Gateway-Adresse meiden, und statische Leases müssen eindeutig sein und im Subnetz liegen. Statische Leases werden mit dem Namen des Servers nach /ip dhcp-server lease geschrieben, sodass jedes Gerät stets dieselbe Adresse erhält.

      Tipps

      • Sie planen die Adressierung? Der Subnetzrechner zeigt Host-Bereich und Größe jedes Präfixes.
      • Ein DHCP-Server pro VLAN: Legen Sie zuerst die VLAN-Interfaces mit dem VLAN-Generator an und führen Sie dieses Tool dann einmal pro VLAN aus.
      • Beantwortet der Router DNS, stellen Sie sicher, dass die Firewall DNS aus dem Internet verwirft.
