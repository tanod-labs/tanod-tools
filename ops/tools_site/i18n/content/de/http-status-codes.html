HTTP-Statuscodes verstehen

Jede HTTP-Antwort beginnt mit einem dreistelligen Statuscode, der dem Client sagt, was mit seiner Anfrage passiert ist. Die erste Ziffer gibt die Familie an: 1xx für Zwischenmeldungen, 2xx für Erfolg, 3xx für Weiterleitung, 4xx für ein Problem mit der Anfrage und 5xx für einen Fehler auf dem Server. Ein Programm, das einen bestimmten Code nicht kennt, kann anhand dieser ersten Ziffer trotzdem richtig reagieren; deshalb lassen sich neue Codes einführen, ohne alte Clients zu stören.

Die offizielle Liste führt die IANA in der HTTP Status Code Registry, die Bedeutungen sind in RFC 9110 (HTTP Semantics) und einigen weiteren RFCs für WebDAV und Erweiterungen festgelegt. Die Reason Phrase nach der Nummer, etwa Not Found, ist nur eine Beschriftung; HTTP/2 und HTTP/3 übertragen sie gar nicht. Einige Phrasen wurden 2022 umbenannt, so heißt 413 jetzt Content Too Large und 422 Unprocessable Content.

Server außerhalb der Standards erfinden auch eigene Codes. nginx protokolliert 499, wenn ein Client auflegt, und Cloudflare verwendet 520 bis 526 für Fehler zwischen seinem Netzwerk und Ihrem Ursprungsserver. Sie erscheinen hier in einer eigenen Gruppe, damit sie nicht mit registrierten Codes verwechselt werden. Denken Sie bei der Fehlersuche daran, dass der Code, den Sie sehen, von einem Proxy oder CDN vor Ihrer Anwendung stammen kann und nicht von der Anwendung selbst.

Tipps

  • Eine fehlschlagende Anfrage mit Sonderzeichen in der Adresse? Kodieren oder dekodieren Sie sie mit URL kodieren und dekodieren.
  • Lesen Sie den Antwort-Body eines API-Fehlers mit JSON formatieren und validieren.
  • Ein 403 für einen bestimmten Browser oder Bot? Prüfen Sie mit User-Agent analysieren, was der Client sendet.
