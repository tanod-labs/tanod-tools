SQL lesbar machen


Eine Datenbank liest eine Abfrage gleich, ob sie in einer Zeile steht oder in vierzig. Deshalb kommen Abfragen aus Logs, ORMs und Monitoring-Tools so oft als ein einziger ununterbrochener String an. Wenn Sie SQL formatieren, steht jede Hauptklausel (SELECT, FROM, WHERE, GROUP BY, ORDER BY) in einer eigenen Zeile, und Spalten, Bedingungen und Unterabfragen werden darunter eingerückt. So erkennen Sie die Struktur der Abfrage auf einen Blick und bemerken etwa eine fehlende Join-Bedingung.


Das Layout richtet sich nach dem gewählten Dialekt, denn Wörter und Symbole unterscheiden sich zwischen Datenbanken. Ein PostgreSQL-Cast wie price::numeric, ein nummerierter Parameter wie $1, ein MySQL-Name in Backticks, eine Oracle-Klausel CONNECT BY und ein SQL-Server-TOP 10 sind jeweils in einem Dialekt gültig und in einem anderen ein Syntaxfehler. Platzhalter für gebundene Parameter (?, $1, :name, @name) werden erkannt und nicht verändert.


Die Schreibweise der Schlüsselwörter hat keinen Einfluss darauf, wie eine Abfrage läuft; sie ist reine Stilfrage. Ein Formatierer, der die Grammatik versteht, kann sie gefahrlos ändern, weil er weiß, welche Wörter Schlüsselwörter sind und welche Spaltennamen oder Text in Anführungszeichen.

  • Sie vergleichen eine Abfrage vor und nach einer Änderung? Formatieren Sie beide mit denselben Einstellungen und vergleichen Sie sie mit Texte vergleichen.
