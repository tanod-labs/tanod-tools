Von YAML zu JSON


YAML und JSON beschreiben dieselbe Art von Daten: Mappings, Listen und einfache Werte. YAML wird von Menschen geschrieben, mit Einrückung statt Klammern, mit Kommentaren und Abkürzungen wie Ankern; JSON erwarten die meisten Programme und APIs. YAML in JSON umzuwandeln ist häufig nötig, wenn ein Kubernetes-Manifest, eine Compose-Datei oder eine OpenAPI-Beschreibung an etwas übergeben werden muss, das nur JSON liest.


Manche YAML-Funktionen haben keine Entsprechung in JSON, deshalb löst der Konverter sie auf. Ein Anker (&base) markiert einen Block, den ein Alias (*base) wiederverwenden kann, und ein Merge-Key (<<) kopiert die Einträge eines Mappings in ein anderes; in JSON wird daraus jeweils eine vollständige Kopie. Kommentare fallen weg, weil JSON sie nicht aufnehmen kann. Eine Datei mit mehreren durch --- getrennten Dokumenten wird zu einem JSON-Array.


Die Typregeln folgen YAML 1.2: true und false sind Boolesche Werte, null und ~ sind null, Zahlen sind Zahlen, und alles andere, auch yes und 2024-05-01, ist Text. Syntaxfehler kommen mit Zeile und Spalte; die häufigsten Ursachen sind ein Tab als Einrückung, ein im selben Mapping wiederholter Schlüssel und ein Wert, der nicht unter seinem Schlüssel eingerückt ist.
