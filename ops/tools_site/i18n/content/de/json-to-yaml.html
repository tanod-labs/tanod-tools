JSON in gut lesbares YAML umwandeln


YAML ist im Grunde eine menschenfreundlichere Schreibweise für dieselben Daten, die JSON enthält. Statt geschweifter Klammern und Anführungszeichen gibt es Einrückungen und schlichte Wörter, deshalb wird die Konfiguration für Kubernetes, Compose und CI-Systeme meist in YAML geschrieben. Wenn Sie JSON in YAML umwandeln, etwa eine API-Antwort oder ein generiertes Manifest, ist die Umwandlung mechanisch, aber ein Detail verlangt Sorgfalt: YAML bestimmt den Typ eines Werts danach, wie er aussieht.


In YAML ist ein nacktes true ein Boolean, null ist null und 1.0 eine Zahl. Ein JSON-String, der zufällig so aussieht, etwa "null", "1.0" oder "0x1F", muss im YAML in Anführungszeichen stehen, sonst ändert er beim Einlesen seinen Typ. Der Konverter setzt genau diese Strings in Anführungszeichen, dazu leere Strings und Text, der mit Zeichen beginnt, die in YAML eine Bedeutung haben, und prüft die Ausgabe anschließend, indem er sie wieder einliest.


Mehrzeiliger Text wird zu einem Literal-Block, der viel leichter zu lesen ist als ein langer String mit \n-Escapes. Leere Objekte und Arrays werden als {} und [] geschrieben. Da JSON keine Kommentare kennt, beginnt das YAML ohne Kommentare; Sie können danach eigene ergänzen.
