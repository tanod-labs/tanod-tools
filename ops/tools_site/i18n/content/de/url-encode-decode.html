Was URL-Encoding macht

Eine URL darf nur eine begrenzte Menge von ASCII-Zeichen enthalten, und einige davon haben eine Aufgabe: / trennt Pfadsegmente, ? leitet die Query ein, & und = teilen sie in Namen und Werte, # leitet das Fragment ein. Die Prozentkodierung (URL-Encoding) schreibt jedes andere Byte als % gefolgt von zwei Hexadezimalziffern. So kann ein Wert wie R&D / 2026 in einem Query-String stehen, ohne für Struktur gehalten zu werden: R%26D%20%2F%202026.

Text wird zunächst in UTF-8-Bytes umgewandelt, deshalb wird ein einzelner Umlaut zu zwei Escape-Sequenzen und ein Emoji zu vier. Beim Dekodieren läuft der Vorgang rückwärts, und es wird geprüft, ob die Bytes gültiges UTF-8 ergeben. Dieses Tool dekodiert mit einem eigenen, strengen Leser: Statt einer allgemeinen Fehlermeldung wie „URI malformed“ sagt es Ihnen, welche Sequenz fehlerhaft ist und wo.

Die drei Modi passen zu den drei üblichen Situationen. Kodieren Sie einen einzelnen Wert (Komponente), wenn Sie einen Query-Parameter oder ein Pfadsegment zusammenbauen. Kodieren Sie eine ganze URL nur, wenn Sie eine vollständige Adresse mit Leerzeichen oder Nicht-ASCII-Buchstaben haben. Formulardaten verwenden Sie für den Body eines Formular-POSTs oder einen Query-String, der so aufgebaut ist, wie HTML-Formulare ihn bauen.

Tipps

  • Sie möchten statt Escape-Sequenzen einen sauberen, lesbaren Pfad? Erstellen Sie ihn mit dem Slug-Generator.
  • Binärdaten in einer URL sind meist Base64url, keine Prozentkodierung: Versuchen Sie Base64 kodieren und dekodieren.
  • Ein Token in einem Query-String, das mit eyJ beginnt, ist vermutlich ein JWT. Lesen Sie es mit dem JWT-Decoder.
