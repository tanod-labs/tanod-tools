Du YAML au JSON


Le YAML et le JSON décrivent le même type de données : des mappings, des listes et des valeurs simples. Le YAML est écrit par des humains, avec de l'indentation au lieu d'accolades, des commentaires et des raccourcis comme les ancres ; le JSON est ce qu'attendent la plupart des programmes et des API. Convertir du YAML en JSON est courant quand un manifeste Kubernetes, un fichier Compose ou une description OpenAPI doit être fourni à un outil qui ne lit que le JSON.


Certaines fonctions du YAML n'ont pas d'équivalent en JSON : le convertisseur les résout donc. Une ancre (&base) marque un bloc qu'un alias (*base) peut réutiliser, et une clé de fusion (<<) copie les entrées d'un mapping dans un autre ; en JSON, chacun devient une copie complète. Les commentaires sont supprimés, car le JSON ne peut pas les contenir. Un fichier avec plusieurs documents séparés par --- devient un tableau JSON.


Les règles de types suivent YAML 1.2 : true et false sont des booléens, null et ~ valent null, les nombres sont des nombres, et tout le reste, y compris yes et 2024-05-01, est du texte. Les erreurs de syntaxe indiquent une ligne et une colonne ; les causes les plus fréquentes sont une tabulation utilisée pour l'indentation, une clé répétée dans le même mapping et une valeur non indentée sous sa clé.
