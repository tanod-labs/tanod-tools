      DHCP sur RouterOS, pièce par pièce

      RouterOS répartit un serveur DHCP en trois endroits, et une pièce manquante est la raison habituelle pour laquelle des clients n'obtiennent aucune adresse. Le pool est simplement un ensemble nommé de plages d'adresses. Le serveur écoute sur une interface et attribue des adresses de son pool. L'entrée network est associée par sous-réseau et contient les options envoyées avec chaque bail : passerelle, serveurs DNS, nom de domaine et serveurs NTP. L'interface a aussi besoin de l'adresse propre du routeur dans ce sous-réseau, sinon le serveur n'a aucun réseau à desservir.

      La page vérifie la cohérence des pièces entre elles avant de rien écrire : la passerelle et le pool doivent se trouver dans le sous-réseau, le pool doit éviter les adresses de réseau, de broadcast et de la passerelle, et les baux statiques doivent être uniques et situés dans le sous-réseau. Les baux statiques sont écrits dans /ip dhcp-server lease avec le nom du serveur, pour que chaque appareil reçoive toujours la même adresse.

      Conseils

      • Vous planifiez l'adressage ? Le calculateur de sous-réseau affiche la plage d'hôtes et la taille de n'importe quel préfixe.
      • Un serveur DHCP par VLAN : créez d'abord les interfaces VLAN avec le générateur de VLAN, puis lancez cet outil une fois par VLAN.
      • Si le routeur répond au DNS, assurez-vous que le firewall rejette le DNS venant d'internet.
