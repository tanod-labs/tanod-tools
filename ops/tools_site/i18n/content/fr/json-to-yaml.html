Transformer du JSON en YAML lisible


Pour convertir du JSON en YAML, il faut d'abord savoir que le YAML est surtout une façon plus lisible d'écrire les mêmes données que le JSON. Les accolades et les guillemets laissent place à l'indentation et à des mots simples, c'est pourquoi la configuration de Kubernetes, de Compose ou des systèmes de CI est généralement écrite en YAML. À partir d'un JSON, comme une réponse d'API ou un manifeste généré, la conversion est mécanique, mais un détail demande de l'attention : le YAML déduit le type d'une valeur de son apparence.


En YAML, un true seul est un booléen, null est une valeur nulle et 1.0 est un nombre. Une chaîne JSON qui ressemble à l'une de ces valeurs, comme "null", "1.0" ou "0x1F", doit être mise entre guillemets dans le YAML, sinon elle changera de type à la lecture. Le convertisseur met précisément celles-ci entre guillemets, ainsi que les chaînes vides et les textes qui commencent par des symboles ayant un sens en YAML, puis il vérifie le résultat en le relisant.


Le texte sur plusieurs lignes devient un bloc littéral, bien plus facile à lire qu'une longue chaîne remplie de \n. Les objets et tableaux vides sont écrits {} et []. Comme le JSON n'a pas de commentaires, le YAML n'en contient aucun au départ ; vous pouvez ajouter les vôtres ensuite.
