YAML से JSON तक


YAML और JSON एक ही तरह के डेटा का वर्णन करते हैं: मैपिंग, सूचियाँ और सादे मान। YAML इंसानों के लिखने के लिए है, ब्रेसेस की जगह इंडेंटेशन, कमेंट और एंकर जैसे शॉर्टकट के साथ; JSON वह है जिसकी ज़्यादातर प्रोग्राम और API अपेक्षा करते हैं। जब Kubernetes मैनिफ़ेस्ट, Compose फ़ाइल या OpenAPI विवरण किसी ऐसी चीज़ को देना हो जो सिर्फ़ JSON पढ़ती है, तब इनके बीच बदलना आम है।


YAML की कुछ ख़ूबियों का JSON में कोई समकक्ष नहीं है, इसलिए कन्वर्टर उन्हें सुलझा देता है। एंकर (&base) एक ब्लॉक को चिह्नित करता है जिसे अलियास (*base) दोबारा इस्तेमाल कर सकता है, और मर्ज की (<<) एक मैपिंग की प्रविष्टियाँ दूसरी में कॉपी करती है; JSON में इनमें से हर एक पूरी कॉपी बन जाता है। कमेंट छोड़ दिए जाते हैं, क्योंकि JSON उन्हें रख नहीं सकता। --- से अलग किए कई दस्तावेज़ों वाली फ़ाइल JSON ऐरे बन जाती है।


टाइप के नियम YAML 1.2 का पालन करते हैं: true और false बूलियन हैं, null और ~ null हैं, संख्याएं संख्याएं हैं, और बाकी सब, yes और 2024-05-01 समेत, टेक्स्ट है। सिंटैक्स एरर के साथ लाइन और कॉलम आते हैं, और सबसे आम कारण हैं इंडेंटेशन के लिए इस्तेमाल हुआ टैब, एक ही मैपिंग में दोहराई गई की, और ऐसा मान जो अपनी की के नीचे इंडेंट नहीं है।
