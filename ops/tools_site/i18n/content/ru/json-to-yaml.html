Как превратить JSON в читаемый YAML


YAML — во многом более удобный для человека способ записи тех же данных, что хранит JSON. Скобки и кавычки уступают место отступам и обычным словам, поэтому на нём обычно пишут конфигурации Kubernetes, Compose и систем CI. Если исходить из JSON, например из ответа API или сгенерированного манифеста, преобразование механическое, но одну деталь нужно учесть: YAML определяет тип значения по его виду.


В YAML голое true — логическое значение, null — пустое значение, а 1.0 — число. Строка JSON, похожая на одно из них, например "null", "1.0" или "0x1F", должна быть в YAML взята в кавычки, иначе при чтении изменится её тип. Конвертер берёт в кавычки именно такие строки, а также пустые строки и текст, начинающийся с символов, имеющих в YAML особый смысл, после чего проверяет результат, читая его обратно.


Многострочный текст становится литеральным блоком, который читается гораздо легче, чем длинная строка с экранированием \n. Пустые объекты и массивы записываются как {} и []. Поскольку в JSON нет комментариев, YAML начинается без них; свои комментарии можно добавить потом.
