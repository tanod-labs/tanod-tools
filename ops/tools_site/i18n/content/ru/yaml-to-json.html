От YAML к JSON


YAML и JSON описывают данные одного и того же рода: отображения, списки и простые значения. YAML пишут люди, с отступами вместо фигурных скобок, комментариями и такими сокращениями, как якоря; JSON — то, чего ожидает большинство программ и API. Преобразование между ними распространено, когда манифест Kubernetes, файл Compose или описание OpenAPI нужно передать тому, что читает только JSON.


У некоторых возможностей YAML нет эквивалента в JSON, поэтому конвертер их раскрывает. Якорь (&base) помечает блок, который может использовать алиас (*base), а ключ слияния (<<) копирует записи отображения в другое; в JSON каждый из них превращается в полную копию. Комментарии отбрасываются, потому что JSON не может их хранить. Файл с несколькими документами, разделёнными ---, становится массивом JSON.


Правила типов соответствуют YAML 1.2: true и false — логические значения, null и ~ — null, числа — числа, а всё остальное, включая yes и 2024-05-01, — текст. У синтаксических ошибок указаны строка и столбец, а чаще всего их причины — табуляция вместо пробелов в отступе, повторяющийся в одном отображении ключ и значение, не сдвинутое под своим ключом.
