      DHCP в RouterOS по частям

      В RouterOS DHCP-сервер состоит из трёх частей, и пропуск одной из них — обычная причина того, что клиенты не получают адрес. Пул — это просто именованный набор диапазонов адресов. Сервер слушает один интерфейс и выдаёт адреса из своего пула. Запись network подбирается по подсети и содержит параметры, передаваемые с каждой арендой: шлюз, DNS-серверы, доменное имя и NTP-серверы. Кроме того, на интерфейсе нужен собственный адрес маршрутизатора в этой подсети, иначе серверу нечего обслуживать.

      Страница сверяет части между собой, прежде чем что-либо записать: шлюз и пул должны находиться внутри подсети, пул не должен включать адрес сети, широковещательный адрес и адрес шлюза, а статические аренды должны быть уникальными и находиться внутри подсети. Статические аренды записываются в /ip dhcp-server lease с именем сервера, поэтому каждое устройство всегда получает один и тот же адрес.

      Советы

      • Планируете адресацию? Инструмент «Калькулятор подсетей» показывает диапазон хостов и размер любого префикса.
      • Один DHCP-сервер на каждую VLAN: сначала создайте интерфейсы VLAN в инструменте «Генератор VLAN для MikroTik», затем выполните этот инструмент один раз для каждой VLAN.
      • Если маршрутизатор отвечает на DNS, убедитесь, что файрвол блокирует DNS из интернета; в этом поможет «Генератор файрвола MikroTik».
