Как читать коды состояния HTTP

Каждый ответ HTTP начинается с трёхзначного кода состояния, который сообщает клиенту, что произошло с его запросом. Первая цифра обозначает семейство: 1xx — сообщения о ходе выполнения, 2xx — успех, 3xx — перенаправление, 4xx — проблема в запросе, 5xx — сбой на стороне сервера. Программа, не знающая конкретного кода, всё равно может правильно отреагировать по первой цифре, поэтому новые коды можно добавлять, не ломая старых клиентов.

Официальный список ведётся в реестре IANA HTTP Status Code Registry, а значения описаны в RFC 9110 (HTTP Semantics) и нескольких других RFC для WebDAV и расширений. Поясняющая фраза после номера, например Not Found, — всего лишь подпись; HTTP/2 и HTTP/3 её не передают. Некоторые названия были изменены в 2022 году: 413 теперь Content Too Large, а 422 — Unprocessable Content.

Серверы вне стандартов тоже придумывают свои коды. nginx записывает в журнал 499, когда клиент разорвал соединение, а Cloudflare использует 520–526 для описания сбоев между своей сетью и вашим исходным сервером. Здесь они вынесены в отдельную группу, чтобы их не приняли за зарегистрированные коды. При отладке помните, что код, который вы видите, может исходить от прокси или CDN перед вашим приложением, а не от самого приложения.

Советы

  • Запрос с ошибкой содержит в адресе специальные символы? Закодируйте или декодируйте его в инструменте «Кодирование и декодирование URL».
  • Тело ответа API с ошибкой удобно читать в инструменте «Форматирование и проверка JSON».
  • 403 только для определённого браузера или бота? Проверьте, что отправляет клиент, с помощью «Разбор User-Agent».
