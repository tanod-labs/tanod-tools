Como deixar o SQL legível


Um banco de dados lê uma query do mesmo jeito, esteja ela numa linha ou em quarenta, e é por isso que queries copiadas de logs, ORMs e ferramentas de monitoramento tantas vezes chegam como uma única string contínua. Formatar SQL coloca cada cláusula principal (SELECT, FROM, WHERE, GROUP BY, ORDER BY) na própria linha e indenta as colunas, condições e subqueries abaixo dela, para você ver a estrutura da query de relance e encontrar uma condição de join faltando.


O layout segue o dialeto escolhido, porque as palavras e os símbolos mudam de um banco de dados para outro. Um cast do PostgreSQL como price::numeric, um parâmetro numerado como $1, um nome entre crases do MySQL, uma cláusula CONNECT BY do Oracle e um TOP 10 do SQL Server são válidos num dialeto e erro de sintaxe em outro. Marcadores de parâmetros vinculados (?, $1, :name, @name) são reconhecidos e deixados como estão.


As maiúsculas das palavras-chave não afetam como a query roda, então são puro estilo da casa. Um formatador que entende a gramática pode mudá-las com segurança, porque sabe quais palavras são palavras-chave e quais são nomes de colunas ou texto entre aspas.
