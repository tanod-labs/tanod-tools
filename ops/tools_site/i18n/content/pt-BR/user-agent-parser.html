Client Hints do seu navegador

O que um user agent revela e o que ele esconde

Um analisador de user agent existe porque essa string nasceu como uma forma de o servidor ver qual navegador estava pedindo a página, para enviar uma versão que funcionasse nele. Os navegadores então passaram a copiar os nomes uns dos outros para receber as páginas boas, e é por isso que uma string do Chrome hoje também diz Mozilla, AppleWebKit, KHTML, Gecko e Safari. Um analisador contorna isso testando padrões em uma ordem cuidadosa e escolhendo a correspondência mais específica.

A string também está sendo encurtada de propósito. A User-Agent reduction do Chrome fixa a versão do Windows em NT 10.0, a do macOS em 10_15_7, o modelo Android em K e o número de build em 0.0.0, para que a string deixe de ser uma boa impressão digital. Os detalhes não sumiram: uma página que os pede via Client Hints recebe a versão da plataforma, a arquitetura, o modelo e a versão completa do navegador, e o navegador do visitante decide se responde.

Use a string para decisões genéricas e para logs, não para confiança. Crawlers e ferramentas de linha de comando como o curl enviam as próprias strings curtas, e qualquer coisa pode ser falsificada. Se você está caçando um bug de layout, a detecção de recursos na página é mais confiável do que ler o nome do navegador.

Dicas

  • Um log de servidor cheio de respostas 403 ou 429 para um cliente? Consulte os códigos em Códigos de status HTTP.
  • User agents em URLs ou query strings muitas vezes estão com percent-encoding; decodifique-os com Codificar e decodificar URL.
  • Cabeçalhos copiados de uma requisição às vezes trazem valores em Base64; leia-os com Codificar e decodificar Base64.
