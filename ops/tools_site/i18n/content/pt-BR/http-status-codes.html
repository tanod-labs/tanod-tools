Como ler os códigos de status HTTP

Toda resposta HTTP começa com um código de status de três dígitos que diz ao cliente o que aconteceu com a requisição. O primeiro dígito indica a família: 1xx para mensagens de andamento, 2xx para sucesso, 3xx para redirecionamento, 4xx para um problema na requisição e 5xx para uma falha no servidor. Um programa que não conhece um código específico ainda consegue agir corretamente olhando esse primeiro dígito, e é por isso que novos códigos podem ser adicionados sem quebrar clientes antigos.

A lista oficial é mantida no registro de códigos de status HTTP da IANA, e os significados estão descritos na RFC 9110 (HTTP Semantics) e em algumas outras RFCs para WebDAV e extensões. A frase depois do número, como Not Found, é só um rótulo; o HTTP/2 e o HTTP/3 nem a transmitem. Algumas frases foram renomeadas em 2022, então o 413 agora é Content Too Large e o 422 é Unprocessable Content.

Servidores fora dos padrões também inventam códigos. O nginx registra 499 quando um cliente desliga, e o Cloudflare usa de 520 a 526 para descrever falhas entre a rede dele e a sua origem. Eles aparecem aqui em um grupo separado para não serem confundidos com códigos registrados. Ao depurar, lembre-se de que o código que você vê pode vir de um proxy ou CDN na frente da sua aplicação, e não da aplicação em si.

Dicas

  • Uma requisição falhando com caracteres especiais no endereço? Codifique ou decodifique-o com Codificar e decodificar URL.
  • Leia o corpo da resposta de um erro de API com Formatar e validar JSON.
  • Um 403 para um navegador ou bot específico? Veja o que o cliente envia com o Analisador de user agent.
