O que a codificação de URL faz

Codificar e decodificar URL é necessário porque uma URL só pode conter um conjunto limitado de caracteres ASCII, e alguns deles têm função: / separa segmentos do caminho, ? inicia a query, & e = a dividem em nomes e valores, # inicia o fragmento. O percent-encoding escreve qualquer outro byte como % seguido de dois dígitos hexadecimais, então um valor como R&D / 2026 pode viajar dentro de uma query string sem ser confundido com estrutura: R%26D%20%2F%202026.

O texto é primeiro transformado em bytes UTF-8, e é por isso que uma letra acentuada vira dois escapes e um emoji vira quatro. A decodificação faz o caminho inverso e verifica se os bytes formam UTF-8 válido. Esta ferramenta decodifica com um leitor próprio e rigoroso, então, em vez de um erro genérico "URI malformed", ela diz qual escape está quebrado e onde.

Os três modos correspondem às três situações mais comuns. Codifique um valor único (componente) quando estiver montando um parâmetro de query ou um segmento de caminho. Codifique uma URL inteira só quando tiver um endereço completo com espaços ou letras não ASCII. Use dados de formulário para o corpo de um envio de formulário ou para uma query string montada do jeito que os formulários HTML montam.

Dicas

  • Precisa de um caminho limpo e legível em vez de escapes? Crie um com o Gerador de slug.
  • Dados binários em uma URL costumam estar em Base64url, não em percent-encoding: experimente Codificar e decodificar Base64.
  • Um token em uma query string que começa com eyJ provavelmente é um JWT. Leia-o com o Decodificador de JWT.
