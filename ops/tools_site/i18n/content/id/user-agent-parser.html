Client Hints dari browser Anda

Apa yang diungkapkan user agent, dan apa yang disembunyikannya

Pengurai user agent ini membaca string yang awalnya dibuat agar server bisa melihat browser mana yang meminta halaman, sehingga server bisa mengirim halaman yang berfungsi di browser itu. Browser lalu saling meniru nama satu sama lain agar mendapat halaman yang bagus, itulah sebabnya string Chrome saat ini juga menyebut Mozilla, AppleWebKit, KHTML, Gecko dan Safari. Parser mengatasinya dengan menguji pola dalam urutan yang cermat dan memilih kecocokan yang paling spesifik.

String ini juga sengaja dipersingkat. User-Agent reduction di Chrome membuat versi Windows tetap di NT 10.0, versi macOS di 10_15_7, model Android di K dan nomor build di 0.0.0, sehingga string tersebut tidak lagi menjadi sidik jari yang bagus. Detailnya tidak hilang: halaman yang memintanya lewat Client Hints mendapat versi platform, arsitektur, model dan versi lengkap browser, dan browser pengunjunglah yang memutuskan apakah akan menjawab.

Gunakan string ini untuk keputusan kasar dan log, bukan untuk kepercayaan. Crawler dan alat command line seperti curl mengirim string pendek mereka sendiri, dan apa pun bisa dipalsukan. Jika Anda sedang memburu bug tata letak, deteksi fitur di halaman lebih andal daripada membaca nama browser.

Tips

  • Log server penuh respons 403 atau 429 untuk satu klien? Cari arti kodenya di Kode status HTTP.
  • User agent di URL atau query string sering di-percent-encode; decode dengan Encode dan decode URL.
  • Header yang disalin dari request kadang berisi nilai Base64; baca dengan Encode dan decode Base64.
