Apa yang dilakukan URL encoding

URL encode dan decode diperlukan karena URL hanya boleh berisi sekumpulan karakter ASCII terbatas, dan sebagian di antaranya punya tugas: / memisahkan segmen path, ? memulai query, & dan = membaginya menjadi nama dan nilai, # memulai fragmen. Percent-encoding menulis byte lain sebagai % diikuti dua digit heksadesimal, sehingga nilai seperti R&D / 2026 bisa dibawa di dalam query string tanpa disangka bagian dari struktur: R%26D%20%2F%202026.

Teks diubah dulu menjadi byte UTF-8, itulah sebabnya satu huruf beraksen menjadi dua escape dan satu emoji menjadi empat. Decode membalik prosesnya dan memeriksa apakah byte-nya membentuk UTF-8 yang valid. Alat ini men-decode dengan pembaca ketatnya sendiri, jadi alih-alih pesan umum "URI malformed", alat ini memberi tahu escape mana yang rusak dan di mana letaknya.

Ketiga mode sesuai dengan tiga situasi umum. Encode satu nilai (komponen) saat Anda menyusun parameter query atau segmen path. Encode URL lengkap hanya jika Anda punya alamat utuh yang berisi spasi atau huruf non-ASCII. Gunakan data form untuk isi kiriman form atau query string yang disusun seperti cara form HTML menyusunnya.

Tips

  • Butuh path yang bersih dan mudah dibaca, bukan deretan escape? Buat dengan Generator slug.
  • Data biner di URL biasanya berupa Base64url, bukan percent-encoding: coba Encode dan decode Base64.
  • Token di query string yang diawali eyJ kemungkinan besar adalah JWT. Baca dengan Decoder JWT.
