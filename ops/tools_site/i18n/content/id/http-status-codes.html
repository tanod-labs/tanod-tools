Membaca kode status HTTP

Setiap respons HTTP diawali kode status tiga digit yang memberi tahu klien apa yang terjadi pada permintaannya. Digit pertama menunjukkan kelompoknya: 1xx untuk pesan progres, 2xx untuk keberhasilan, 3xx untuk pengalihan (redirect), 4xx untuk masalah pada permintaan dan 5xx untuk kegagalan di server. Program yang tidak mengenal sebuah kode tertentu tetap bisa bertindak benar dengan melihat digit pertama itu, itulah sebabnya kode baru bisa ditambahkan tanpa merusak klien lama.

Daftar resminya disimpan di IANA HTTP Status Code Registry, dan artinya ditulis di RFC 9110 (HTTP Semantics) serta beberapa RFC lain untuk WebDAV dan ekstensi. Reason phrase setelah angka, seperti Not Found, hanyalah label; HTTP/2 dan HTTP/3 tidak membawanya. Beberapa frasa diganti namanya pada 2022, jadi 413 kini bernama Content Too Large dan 422 bernama Unprocessable Content.

Server di luar standar juga membuat kode sendiri. nginx mencatat 499 ketika klien memutus koneksi, dan Cloudflare memakai 520 sampai 526 untuk menggambarkan kegagalan antara jaringannya dan server origin Anda. Kode-kode itu ditampilkan di sini dalam grup terpisah agar tidak dikira kode terdaftar. Saat debugging, ingat bahwa kode yang Anda lihat bisa berasal dari proxy atau CDN di depan aplikasi Anda, bukan dari aplikasinya sendiri.

Tips

  • Request gagal karena alamatnya berisi karakter khusus? Encode atau decode dengan Encode dan decode URL.
  • Baca body respons dari error API dengan Format dan validasi JSON.
  • Dapat 403 untuk browser atau bot tertentu? Cek apa yang dikirim klien dengan Pengurai user agent.
