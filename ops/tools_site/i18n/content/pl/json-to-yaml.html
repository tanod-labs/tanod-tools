Zamiana JSON na czytelny YAML


YAML to w dużej mierze bardziej przyjazny człowiekowi sposób zapisu tych samych danych, które przechowuje JSON. Nawiasy klamrowe i cudzysłowy ustępują wcięciom i zwykłym słowom, dlatego konfiguracje Kubernetesa, Compose i systemów CI zwykle pisze się właśnie w nim. Gdy punktem wyjścia jest JSON, na przykład odpowiedź API lub wygenerowany manifest, konwersja jest mechaniczna, ale jeden szczegół wymaga uwagi: YAML określa typ wartości po tym, jak ona wygląda.


W YAML samo true to wartość logiczna, null to null, a 1.0 to liczba. Ciąg JSON, który tak wygląda, na przykład "null", "1.0" lub "0x1F", musi być w YAML ujęty w cudzysłów, w przeciwnym razie zmieni typ po odczytaniu. Konwerter ujmuje w cudzysłów dokładnie takie ciągi, a także puste ciągi i tekst zaczynający się od symboli mających w YAML znaczenie, a potem sprawdza wynik, odczytując go z powrotem.


Tekst wielowierszowy staje się blokiem literalnym, który czyta się znacznie łatwiej niż długi ciąg z sekwencjami \n. Puste obiekty i tablice są zapisywane jako {} i []. Ponieważ JSON nie ma komentarzy, YAML zaczyna się bez nich; własne możesz dodać później.
