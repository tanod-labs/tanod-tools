Jak czytać kody statusu HTTP

Każda odpowiedź HTTP zaczyna się od trzycyfrowego kodu statusu, który informuje klienta, co stało się z jego żądaniem. Pierwsza cyfra wskazuje rodzinę: 1xx to komunikaty o postępie, 2xx sukces, 3xx przekierowanie, 4xx problem z żądaniem, a 5xx awaria po stronie serwera. Program, który nie zna danego kodu, i tak może zachować się poprawnie, patrząc na tę pierwszą cyfrę, dlatego nowe kody można dodawać bez psucia starych klientów.

Oficjalna lista jest prowadzona w rejestrze IANA HTTP Status Code Registry, a znaczenia opisano w RFC 9110 (HTTP Semantics) i kilku innych RFC dla WebDAV i rozszerzeń. Fraza opisowa po numerze, na przykład Not Found, jest tylko etykietą; HTTP/2 i HTTP/3 jej nie przesyłają. Kilka fraz zmieniono w 2022 roku, więc 413 to teraz Content Too Large, a 422 to Unprocessable Content.

Serwery spoza standardów też wymyślają własne kody. nginx zapisuje w logach 499, gdy klient się rozłączy, a Cloudflare używa 520–526 do opisu awarii między swoją siecią a Twoim serwerem źródłowym. Tutaj są w osobnej grupie, aby nie pomylić ich z kodami zarejestrowanymi. Podczas diagnozowania pamiętaj, że widziany kod może pochodzić z serwera proxy lub CDN przed aplikacją, a nie z samej aplikacji.

Wskazówki

  • Żądanie z błędem ma w adresie znaki specjalne? Zakoduj lub zdekoduj go w narzędziu Koduj i dekoduj URL.
  • Treść odpowiedzi z błędem API odczytasz w narzędziu Formatuj i waliduj JSON.
  • Kod 403 dla konkretnej przeglądarki lub bota? Sprawdź, co wysyła klient, w narzędziu Analizator user agent.
