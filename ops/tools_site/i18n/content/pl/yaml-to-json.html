Od YAML do JSON


YAML i JSON opisują ten sam rodzaj danych: mapowania, listy i proste wartości. YAML piszą ludzie, używając wcięć zamiast nawiasów klamrowych, komentarzy i skrótów takich jak kotwice; JSON to to, czego oczekuje większość programów i API. Konwersja między nimi jest częsta, gdy manifest Kubernetes, plik Compose lub opis OpenAPI trzeba przekazać czemuś, co czyta tylko JSON.


Niektóre cechy YAML nie mają odpowiednika w JSON, więc konwerter je rozwiązuje. Kotwica (&base) oznacza blok, który alias (*base) może wykorzystać ponownie, a klucz scalający (<<) kopiuje wpisy mapowania do innego; w JSON każde z nich staje się pełną kopią. Komentarze są usuwane, ponieważ JSON nie może ich przechowywać. Plik z kilkoma dokumentami rozdzielonymi przez --- staje się tablicą JSON.


Reguły typów są zgodne z YAML 1.2: true i false to wartości logiczne, null i ~ to null, liczby to liczby, a wszystko inne, w tym yes i 2024-05-01, to tekst. Błędy składni mają wiersz i kolumnę, a najczęstsze przyczyny to tabulator użyty do wcięcia, klucz powtórzony w tym samym mapowaniu oraz wartość, która nie jest wcięta pod swoim kluczem.
