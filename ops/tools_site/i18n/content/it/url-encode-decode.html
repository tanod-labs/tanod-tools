Cosa fa la codifica degli URL

Un URL può contenere solo un insieme limitato di caratteri ASCII, e alcuni di essi hanno un compito: / separa i segmenti del percorso, ? avvia la query, & e = la dividono in nomi e valori, # avvia il frammento. Il percent-encoding scrive qualsiasi altro byte come % seguito da due cifre esadecimali, così un valore come R&D / 2026 può viaggiare in una query string senza essere scambiato per struttura: R%26D%20%2F%202026.

Il testo viene prima trasformato in byte UTF-8, ed è per questo che una lettera accentata diventa due escape e un'emoji ne diventa quattro. La decodifica inverte il processo e verifica che i byte formino UTF-8 valido. Questo strumento decodifica con un proprio lettore rigoroso, quindi invece di un generico errore "URI malformed" ti dice quale escape è errato e dove.

Le tre modalità corrispondono alle tre situazioni più comuni. Codifica un singolo valore (componente) quando costruisci un parametro di query o un segmento di percorso. Codifica un URL completo solo quando hai un indirizzo intero con spazi o lettere non ASCII. Usa i dati di modulo per il corpo di un invio di modulo o per una query string costruita come la costruiscono i moduli HTML.

Consigli

  • Ti serve un percorso pulito e leggibile invece di escape? Creane uno con il Generatore di slug.
  • I dati binari in un URL di solito sono Base64url, non percent-encoding: prova Codifica e decodifica Base64.
  • Un token in una query string che inizia con eyJ è probabilmente un JWT. Leggilo con il Decodificatore JWT.
