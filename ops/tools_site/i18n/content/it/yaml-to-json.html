Da YAML a JSON


YAML e JSON descrivono lo stesso tipo di dati: mappature, liste e valori semplici. YAML è scritto dalle persone, con il rientro al posto delle graffe, i commenti e scorciatoie come le ancore; JSON è ciò che si aspettano la maggior parte dei programmi e delle API. Convertire dall'uno all'altro è comune quando un manifest Kubernetes, un file Compose o una descrizione OpenAPI deve essere dato a qualcosa che legge solo JSON.


Alcune funzionalità di YAML non hanno un equivalente JSON, quindi il convertitore le risolve. Un'ancora (&base) contrassegna un blocco che un alias (*base) può riusare, e una merge key (<<) copia le voci di una mappatura in un'altra; in JSON ognuna di queste diventa una copia completa. I commenti vengono eliminati, perché JSON non può contenerli. Un file con più documenti separati da --- diventa un array JSON.


Le regole sui tipi seguono YAML 1.2: true e false sono booleani, null e ~ sono null, i numeri sono numeri, e tutto il resto, inclusi yes e 2024-05-01, è testo. Gli errori di sintassi riportano riga e colonna, e le cause più frequenti sono una tabulazione usata per il rientro, una chiave ripetuta nella stessa mappatura e un valore che non è indentato sotto la sua chiave.


Consigli


    
  
  • Devi andare nell'altra direzione? Da JSON a YAML mette tra virgolette valori come "yes" così sopravvivono al viaggio.
