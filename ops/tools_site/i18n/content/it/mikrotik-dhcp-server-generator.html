      DHCP su RouterOS, pezzo per pezzo

      RouterOS tiene un server DHCP in tre punti, e un pezzo mancante è il solito motivo per cui i client non ricevono un indirizzo. Il pool è solo un insieme con nome di intervalli di indirizzi. Il server è in ascolto su un'interfaccia e assegna in lease gli indirizzi del suo pool. La voce network viene abbinata per subnet e contiene le opzioni inviate con ogni lease: gateway, server DNS, nome di dominio e server NTP. L'interfaccia ha inoltre bisogno dell'indirizzo del router in quella subnet, altrimenti il server non ha alcuna rete da servire.

      La pagina verifica i pezzi l'uno rispetto all'altro prima di scrivere qualsiasi cosa: gateway e pool devono trovarsi dentro la subnet, il pool deve evitare gli indirizzi di rete, broadcast e gateway, e i lease statici devono essere univoci e dentro la subnet. I lease statici vengono scritti in /ip dhcp-server lease con il nome del server, così ogni dispositivo riceve sempre lo stesso indirizzo.

      Suggerimenti

      • Stai pianificando gli indirizzi? Il Calcolatore di subnet mostra l'intervallo di host e la dimensione di qualsiasi prefisso.
      • Un server DHCP per VLAN: crea prima le interfacce VLAN con il Generatore di VLAN MikroTik, poi esegui questo strumento una volta per VLAN.
      • Se il router risponde al DNS, assicurati che il firewall scarti il DNS proveniente da Internet.
